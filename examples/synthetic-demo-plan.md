# 合成演示设计

这是待实现的演示计划，不是已经可运行的程序。目标是用少量自写资料展示工程行为，让读者无需真实平台账号、私人内容或生产环境即可检查。

## 演示一：检索与交付恢复

准备三份新写的虚构产品说明，每份约 200 字，使用 `demo-doc-a` 等合成标识。伪造检索与草稿平台返回，不连接真实知识库或微信。

| 场景 | 合成输入 | 预期断言 |
| --- | --- | --- |
| 精确文档范围 | 请求文档 a，服务端误回文档 b | 拒绝范围扩大，不生成可交付结果 |
| 重叠分块 | 两段合法重叠与一段冲突重叠 | 合法重建不重复；冲突显式报错 |
| 空结果与依赖失效 | 合法零命中、精排失败分别返回 | 两者状态不同；失败不能当无重复放行 |
| 创建超时 | 伪平台已保存但客户端丢失响应 | 回查复用原 ID，创建计数保持 1 |
| 结果仍不确定 | 创建超时且查不到唯一匹配 | 停止重发，保留待核对状态 |
| 内容被更改 | 去重报告产生后修改正文 | 原报告失效，拒绝交付 |
| 部分阶段成功 | 草稿成功、博客失败 | 保留草稿身份，仅恢复未完成阶段 |

最小交付应含测试、固定样例、运行命令和预期输出，不需要训练模型或搭建完整 CMS。以后如增加真实模型模式，应与默认离线模式分开，明确成本与数据传输。

## 演示二：创作审稿与中断恢复

准备完全虚构的“灯塔修理员”短故事：两个人物、一份 10 行设定、一章 300 字草稿和一条合成反馈，不借用原连载或参考小说。

验收流程：

1. 审稿台只发现 `demo-story`，不扫描真实作品目录。
2. 读到草稿并提交“角色动机不清”的合成意见。
3. 明确记录待修订，不自动改正式设定。
4. 关闭并重启演示，从状态文件恢复待修订位置。
5. 导入预写的修订稿，保留前一版和反馈；人工确认后改变状态。
6. 使用越界路径请求时拒绝，不读取演示目录外的文件。

默认生成器只返回本地预写文本，避免 API 费用与输出不确定性。真实模型模式应单独启用，并展示输入范围和保存的任务身份。

## 演示三：Radar 离线信息批次

为现有 Radar 准备自写的两条虚构版本更新、一条重复来源和一条证据不足记录；模型结果使用固定 fixture。预期去重、分类、来源入口、存疑项和静态输出可重复，不发送通知。

所有演示实现前应重新核对原代码边界；本设计不证明原项目已有相同的离线接口或测试。
