# 我怎样与 AI 协作

这些项目由我提出目标和约束，使用 AI 协作完成代码、测试与文档。我不把 AI 辅助开发包装成全部手写，也不把会调用模型 API 包装成训练模型。

我的职责包括：

1. 明确要解决的用户问题、输入输出和不能越过的边界。
2. 决定组件分工与取舍，例如使用已有知识库能力、保持本地工具轻量、让用户保留发布决定。
3. 把任务拆成可检查的范围，要求实现解释失败路径和状态变化。
4. 审阅结果，追踪源码、测试和运行记录；对于不理解的实现继续学习和复核。
5. 对交付作判断，明确哪些完成，哪些只在文档里，哪些仍未验证。

AI 参与代码草拟、故障分析、测试构造、资料整理和文稿修订。最终结果仍可能有错误，编译通过或生成了文档都不能代替实际业务验收。

我的主要经验在业务系统与交付侧。对于具体模块，我会说明自己做出的决策、AI 参与的实现，以及实际执行的核验；可以通过读代码、说明失败路径和修改合成样例来检验这些工作。

面试时可以围绕三个问题核验我的贡献：为什么这样分工？失败时会发生什么？有什么证据证明结果成立？如果还答不完整，我会明确标注并补做合成复现。
